# 단수 카운터 데이터 모델과 RLS 정책

이 문서는 단수 카운터 기능이 쓰는 테이블과 관계, 테이블마다 적용하는 RLS 정책을 정한다. 1차 설계인 퀵 카운터는 서버 테이블을 만들지 않으므로, 지금은 그 이유와 2차 설계에서 정할 항목만 적는다.

## 1차 설계: 테이블 없음

퀵 카운터의 값, 설정, 마지막으로 센 시각은 그 브라우저에만 저장하고 서버로 보내지 않는다(FR-13, AC-14). 그래서 1차 설계에는 `public` 스키마의 테이블, 마이그레이션, RLS 정책이 없다. 브라우저에 저장하는 항목과 형식은 [도메인 모델](domain.md#브라우저-저장-항목)에서 정한다.

## 2차 설계에서 정할 항목

| 항목 | 근거 요구사항 | 먼저 끝나야 하는 설계 |
|---|---|---|
| 카운터, 카운터 연결, 카운트 이력 테이블과 열 | FR-07, FR-19~FR-32 | 002 프로젝트 테이블, 001 회원 테이블 |
| 테이블과 작업마다의 RLS 정책 표 | NFR-10, AC-28 | 001의 현재 회원 ID 식 |
| 퀵 카운터를 프로젝트 카운터로 옮길 때 만드는 행 | FR-16~FR-18 | 002 프로젝트 테이블 |
| 연결이 끊긴 동안 쌓은 조작을 저장하는 순서와 충돌 처리 | FR-33, FR-42, NFR-01 | 이 문서의 카운터 테이블 |

[ERD 개요](../../../architecture/erd-overview.md)의 counters와 counter_events는 개념 모델이며, 정확한 열과 정책은 2차 설계에서 이 문서에 정한다.
