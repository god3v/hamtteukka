# 비주얼 시스템

이 문서는 함뜨까 화면의 색, 글꼴, 간격, 모서리와 공통 컴포넌트 규칙을 정한다. 화면을 만드는 사람은 이 문서의 토큰 이름과 값으로 라이트 모드와 다크 모드를 함께 맞추고, 글자와 바탕의 대비가 WCAG AA 기준을 넘는지 확인할 수 있다. 이 규칙을 정한 이유는 [ADR-0014](../decisions/0014-design-direction.md)에 있다.

## 원칙

- 화면 바탕은 흰색이고 다크 모드에서는 어두운 갈색 계열이다. 영역은 카드보다 구분선과 여백으로 나눈다.
- 강조 색 `accent`는 한 화면의 주요 행동 하나, 활성 하단 탭, 입력창 포커스, 카운터의 +1 버튼에만 쓴다. 선택된 필터 칩은 강조 색이 아니라 `ink`로 채운다.
- 컴포넌트는 색 값을 직접 쓰지 않고 아래 토큰 이름만 쓴다. `apps/web`에서는 같은 이름의 Tailwind 색(`bg-surface`, `text-ink` 등)으로 쓴다.
- 글자와 바탕의 조합은 WCAG AA(본문 4.5:1)를 넘어야 한다. 새 조합을 쓰면 [대비 확인](#대비-확인) 표에 추가한다.
- 모든 화면은 라이트 모드와 다크 모드에서 모두 확인한다([헌법 P-12](../constitution.md)).

## 글꼴

- 글꼴은 Pretendard 한 가지만 쓴다. Pretendard를 불러오지 못하면 Apple SD Gothic Neo, Noto Sans KR, 맑은 고딕 순서로 시스템 글꼴을 쓴다.
- 값이 바뀌는 숫자(카운터 값, 단수, 파일 크기)에는 고정폭 숫자(`font-variant-numeric: tabular-nums`)를 쓴다. 숫자가 바뀔 때 글자 폭이 흔들리지 않게 하려는 규칙이다.
- 한국어 문장은 단어 단위로 줄을 바꾼다(`word-break: keep-all`).
- 입력창 글자는 16px로 쓴다. iOS Safari는 글자가 16px보다 작은 입력창을 누르면 화면을 확대하기 때문이다.

| 이름 | 크기와 줄 높이 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| `counter-xl` | 88px / 1 | 700 | 카운터 화면의 현재 값 |
| `counter-m` | 48px / 1 | 700 | 홈 화면 퀵 카운터의 값 |
| `title-1` | 22px / 1.35 | 700 | 페이지 제목, 프로젝트 이름. 자간 -0.4px |
| `title-2` | 17px / 1.4 | 700 | 구역 제목 |
| `body` | 15px / 1.6 | 400 | 본문. 목록 행의 제목은 600으로 쓴다 |
| `label` | 13px / 1.4 | 600 | 입력창 이름, 정렬 선택, 칩 |
| `caption` | 12px / 1.5 | 400 | 날짜, 설명, 보조 정보 |
| `micro` | 11px / 1.3 | 600 | 상태 배지, 하단 탭 이름 |

## 간격과 크기

- 간격은 4px 단위로 4, 8, 12, 16, 20, 24, 32px을 쓴다.
- 화면 좌우 여백은 16px이다. 구역 사이는 20~24px, 목록 행의 위아래 안쪽 여백은 10~12px이다.
- 누르는 영역은 가로와 세로 모두 44px 이상으로 만든다. 아이콘이 이보다 작으면 누르는 영역을 넓힌다.
- 아이콘은 선 굵기가 같은 선형 아이콘 한 세트만 쓴다. 크기는 하단 탭 21px, 앱 바 20px, 목록 행 18px이다.

## 모서리

| 값 | 쓰는 곳 |
|---|---|
| 4px | 상태 배지 |
| 6px | 버튼, 입력창 |
| 8px | 카드, 썸네일, 아이콘 상자 |
| 12px | 바텀 시트의 위쪽 모서리, 이어서 뜨기 바, 카운터 화면의 버튼 |
| 완전히 둥글게 | 칩, 프로필 자리의 원 |

## 컴포넌트

| 컴포넌트 | 규칙 |
|---|---|
| 앱 바 | 높이 50px. 탭의 첫 화면은 왼쪽에 `title-1` 제목을 두고, 홈만 워드마크를 둔다. 하위 화면은 왼쪽에 뒤로 버튼을 둔다. 오른쪽에는 아이콘 버튼을 둔다 |
| 주요 버튼 | 높이 44px, `accent` 바탕, `on-accent` 글자, 15px 600. 한 화면에 하나만 둔다 |
| 보조 버튼 | `line-strong` 테두리, `ink` 글자 |
| 글자 버튼 | 바탕과 테두리 없이 `secondary` 글자 |
| 삭제 버튼 | 글자 버튼에 `danger` 글자. 누르면 확인 창을 연다 |
| 입력창 | 위에 `label` 이름, 높이 44px, `line-strong` 1px 테두리. 포커스를 받으면 `focus` 2px 테두리, 오류가 있으면 `danger` 테두리와 아래 오류 문구 |
| 필터 칩 | `line` 테두리와 `secondary` 글자. 선택하면 `ink` 바탕과 `surface` 글자로 바꾼다 |
| 상태 배지 | `micro` 글자와 4px 모서리. 색은 아래 [상태 배지](#상태-배지) 표를 따른다 |
| 목록 행 | 카드로 감싸지 않고 `line` 구분선으로 나눈다. 썸네일 50px, 제목 `body` 600, 보조 정보 `caption` `muted`. 오른쪽에 상태 배지나 이동 표시(›)를 둔다 |
| 위쪽 글자 탭 | 15px 600. 선택한 탭은 `ink` 글자와 2px `ink` 밑줄, 나머지는 `muted` 글자 |
| 하단 탭 | 아이콘과 `micro` 이름. 활성 탭은 `accent`, 나머지는 `muted` |
| 이어서 뜨기 바 | `float` 바탕, 12px 모서리, 하단 탭 위에 띄운다. 왼쪽에 프로젝트·카운터 이름(`on-float-muted` 11px)과 값(16px 700), 오른쪽에 `accent` +1 버튼을 둔다 |
| 바텀 시트 | `surface` 바탕, 위쪽 모서리 12px, 맨 위에 손잡이. 카운터 화면은 화면 전체 높이로 연다 |
| 확인 창 | 제목은 질문, 그 아래 설명, 버튼은 취소(보조 버튼)와 실행(주요 버튼). 삭제처럼 되돌릴 수 없는 실행 버튼은 `danger` 바탕에 `on-danger` 글자를 쓴다 |
| 토스트 | `float` 바탕과 `on-float` 글자. 이어서 뜨기 바 위에 3초 동안 띄운다 |
| 소셜 로그인 버튼 | 카카오와 구글 버튼은 각 회사의 로그인 버튼 디자인 가이드를 따른다. 이 두 버튼은 강조 색 규칙의 예외다 |

### 상태 배지

| 프로젝트 상태 | 바탕 | 글자 |
|---|---|---|
| 진행 중 | `accent-soft` | `accent-strong` |
| 완성 | 없음, `line` 테두리 | `success` |
| 휴면 | 없음, `line` 테두리 | `secondary` |
| 풀었음 | 없음, `line` 테두리 | `muted` |

프로젝트 상태 네 가지는 [002 요구사항](../specs/002-projects/requirements.md)의 FR-04가 정한다. 진행 중 상태만 바탕을 채워서, 지금 뜨고 있는 작품이 목록에서 먼저 눈에 띄게 한다.
