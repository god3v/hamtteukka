# ADR-0008: 개인 뜨개 도구를 MVP로 정함

이 문서는 함뜨까의 첫 출시 범위(R1 MVP)를 개인 뜨개 도구로 정하고, 도안 배포와 커뮤니티를 그 뒤로 미룬 결정을 설명한다. 독자는 R1에 들어가는 기능과 그 순서를 고른 근거, 다른 출시 순서를 채택하지 않은 이유를 알 수 있다.

## 상태

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (accepted) |

| 이 ADR을 대신하는 새 ADR | 없음 |

## 맥락

함뜨까는 뜨개 프로젝트 기록 도구와 도안 공유를 하나의 웹 서비스로 잇는 것을 목표로 한다. 한 사람이 개발하고 운영하므로, 첫 출시는 사용자가 적어도 가치가 있고 운영 부담이 작아야 했다. 참고 서비스 조사에서 확인한 내용은 다음과 같다([참고 서비스 조사](../research/2026-11-18-reference-services.md)).

- 실노트는 진행 프로젝트, 위시리스트, 단수 카운터, 세탁 전후 게이지 기록, 보유 실 관리를 제공하는 모바일 앱이며, 웹 버전은 확인되지 않았다([Google Play](https://play.google.com/store/apps/details?id=com.chbb.knit_schedule&hl=en_US)). 2026-11-18 조회에서는 두 스토어 페이지가 모두 열리지 않아 스토어에서 내려간 상태로 판단했다(추정).
- 니트플로우는 Apple 기기 전용 뜨개 기록 앱이며 Android와 웹 버전이 없다. 운영자는 사용자가 34,000명 이상이라고 밝히지만 제3자 자료로는 확인하지 못했다([니트플로우](https://www.knitflow.io/ko/)).
- 단수링은 iOS용 단수 카운터 앱이며, 반복 카운트와 실시간 자동 저장이 핵심 기능이다([App Store](https://apps.apple.com/kr/app/%EB%8B%A8%EC%88%98%EB%A7%81/id6737157418)).
- 도아니티는 웹 전용 서비스로 도안 오픈마켓과 익명 커뮤니티를 제공하며, 개인 기록 도구는 제공하지 않는다. 도아니티는 커뮤니티를 먼저 열고 도안 마켓을 나중에 열었다(추정, [도아니티](https://www.doanity.com/)).

정리하면 개인 뜨개 도구를 제공하는 국내 서비스는 모바일 앱 중심이고 웹 버전이 확인되지 않았으며, 웹 서비스인 도아니티에는 개인 도구가 없다.

## 결정

R1 MVP는 아래 개인 뜨개 도구로 구성한다. R0 기반에서는 이 기능들이 쓸 계정과 화면 틀을 먼저 만든다.

| 기능 명세 | 포함 기능 | 기능 ID |
|---|---|---|
| [002 뜨개 프로젝트 기록](../specs/002-projects/requirements.md) | 프로젝트 기록, 위시리스트와 뜰 예정 목록(큐), 세탁 전후 게이지 기록 | F-PROJ-01, F-PROJ-02, F-TOOL-01 |
| [003 단수 카운터](../specs/003-row-counter/requirements.md) | 기본 카운터, 로그인 없이 쓰는 퀵 카운터, 파트별 다중 카운터, 반복·연결 카운터 | F-COUNTER-01, F-COUNTER-02, F-COUNTER-03, F-COUNTER-04 |
| [004 내 도안 파일 첨부](../specs/004-pattern-files/requirements.md) | 내 PDF, 링크, 영상 첨부 | F-VIEWER-01 |

R1 이후에는 R1+ 도구 보강, R2 무료 도안 배포, R3 커뮤니티, R4 유료 판매, A1 앱 순서로 진행한다. 각 릴리스의 범위와 진입 조건은 [로드맵](../product/roadmap.md)에서 관리한다.

이 순서를 고른 근거는 두 가지다. 첫째, 개인 도구는 다른 사용자가 없어도 한 사람에게 바로 쓸모가 있으므로 네트워크 효과에 기대지 않는다. 둘째, 비교한 개인 도구 서비스는 모두 웹 버전이 확인되지 않았으므로 웹에서 쓰는 개인 도구로 차이를 만들 수 있다.

## 검토한 대안

### 무료 도안 배포를 먼저 연다

작가가 무료 도안을 올리고 회원이 내려받는 기능(현재 R2 범위)을 첫 출시로 삼는 방안이다. 도안이 쌓이면 사용자를 모으기 쉽다.

그러나 이 방안은 외부 작가가 도안을 올려야 가치가 생긴다. 작가와 이용자가 동시에 있어야 하므로 출시 직후에는 한 사람의 사용자에게 줄 수 있는 가치가 작다. 또한 도안 심사, 관리자 콘솔, 알림처럼 운영에 필요한 기능을 먼저 만들어야 하므로 첫 출시가 늦어진다.

### 커뮤니티를 먼저 연다 (도아니티 순서)

도아니티처럼 커뮤니티를 먼저 열어 사용자를 모은 뒤 도안 마켓을 붙이는 방안이다. 도아니티는 2025년 2월 공지 기준 회원이 약 55,000명이다([도아니티 공지](https://www.doanity.com/p/cm704mjhp000hehfcfz59uds6)).

그러나 새 서비스의 커뮤니티는 글을 쓰는 사람이 적으면 가치가 거의 없다. 또한 게시판을 열면 신고, 차단, 금칙어, 임시조치 기록을 처음부터 운영해야 한다. 정보통신망법 제44조의2는 권리침해 정보의 삭제 요청을 받으면 지체 없이 조치하고 신청인과 게시자에게 알리도록 한다([정보통신망법 제44조의2](https://casenote.kr/법령/정보통신망_이용촉진_및_정보보호_등에_관한_법률/제44조의2)). 한 사람이 첫 출시부터 이 운영을 맡기는 어려우므로 채택하지 않았다.

## 결과

### 좋은 점

- 사용자가 한 명이어도 첫날부터 쓸모가 있다.
- R1에는 다른 회원이 쓴 글이 없으므로 게시물 신고와 임시조치 같은 운영 업무가 생기지 않는다.
- R1에서 쌓인 프로젝트 기록은 R2에서 내 도안함의 도안으로 프로젝트를 시작하는 기능(F-STORE-08)과 이어진다.

### 감수할 점

- 네트워크 효과가 없으므로 사용자가 늘어나는 속도가 느릴 수 있다.
- 이미 자리 잡은 모바일 앱과 비교되므로, 휴대폰 브라우저에서도 카운터를 편하게 쓸 수 있어야 한다. R0의 반응형 모바일 웹(F-UX-01)이 이 조건을 맡는다.
- R3까지는 수익이 없다. 결제를 붙이기 전의 수익 모델은 OD-11에서 정한다([미결정 항목](README.md#미결정-항목)).
